## 3. 模型与输入配置

- 模型：`qwen3.7-text-embedding`，实际返回 1,024 维。
- 官方接口文档记载单条最大 128,000 tokens、每批最多 20 条。本轮实际每批最多 10 条；模型在现有北京端点的可调用性已通过探针和批量调用确认，未做最大长度压力测试。
- tokenizer 由服务端管理；记录响应 `usage`，不宣称本地精确分词。应用另限制单条 UTF-8 字节数与整批字节数，这些是请求大小限制，不伪装成 token 估算。
- 本轮文档批次服务端报告合计 **9,177 tokens**，最大单批 **576 tokens**。不包含探针与检索查询调用用量。
- 服务未提供固定权重 revision。配置明确保留 null，使用“模型别名＋端点＋参数＋固定探针”的运行版本策略，不声称获得不可变底层权重。

来源：[阿里云同步 embedding API 文档](https://www.alibabacloud.com/help/tc/model-studio/text-embedding-synchronous-api)。已将链接、核对日期及应用限制写入 `embedding_profile.json`。

### 探针检测的实际发现

初始余弦距离阈值 1e-6 触发报警。保留失败样本后发现同文复测距离约 1.00e-6 至 1.03e-6，相似度约 0.999999。基于实测将运行阈值设为 1e-4，允许小幅数值变动；该阈值不是语义质量保证。明显不同的探针向量仍会拒绝。

`failed_probe_pair.json`、`probe_repeat_diagnostic.json` 保存诊断，`probe_baseline.json` 保存固定文本与完整基线向量，`model_verification.json` 保存后续检查。构建前后和检索验证前均执行复核。模型、端点、维度或模板变更必须新建 profile；不能混入既有向量空间。

## 4. 检索与校验

两路检索分别为规则与案例；每路均可使用 BM25 与精确余弦检索，再通过 RRF 融合。原文通过来源关联回填。

- 返回预算：最多 8 条规则、4 条案例。冲突组整体纳入预算；无法完整容纳时记录预算缺口，不静默截掉反面规则。
- 来源、版本、审核、撤销和隔离过滤先于排名；上下文引用经哈希/偏移检查。
- 未编码的规则条件仍为 unknown；案例可比性未验证时也不伪装成成立。检索候选不是吉凶结论。
- 缺模型时可见地降级到同一冻结集合的关键词检索；无 hash 假向量替代。
- 本地 review 查询与 production 查询分开，生产发布仍关闭。
