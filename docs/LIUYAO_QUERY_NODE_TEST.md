# LLM 检索规划节点及求职 2/4/5 实测

## 接线

固定规则取用 LLM → core 爻位校验 → 检索规划 LLM → 分路混合检索 → 综合解释。

规划模型选择事实 ID、检索术语与 theory/case 通道。事实描述由程序从 core 拼接，拒绝模型虚构盘面、增加自由断语或未知事实 ID。术语词表允许“进退神”等作为检索目标，但不提前判定其适用或吉凶。

最多生成 4 条补充 query，合并原始 query 后最多 8 条；完整原始 query 保存在 retrieval_plan.baseline_queries。原始 query 沿用全通道，新增 query 分理论/案例通道。模型失败或输出校验失败时回退原始 query。当前词表是受控首版，不是无限制的自由文本改写。

接口响应增加 retrieval_plan，包括状态、冻结盘哈希、原始与最终 query、事实引用和告警。retrieval_trace 增加每条 query 各通道的关键词前 10 名与向量前 10 名（带分数），vector_hits 仍指参与比较的向量数，不是相关案例数。

向量请求使用最多 4 条的小批量，source-evidence 调用等待上限改为 240 秒。首次实测在原有 90 秒等待上限超时，调整后完整解释接口约 55 秒返回。向量失败显式记录降级，不伪装成语义检索成功。

## 结论与限制

理论召回改善，案例精度未明显改善。“占月令”案例排第一说明结构词和日期相似会盖过问事目标；其原文还夹带大量理论与作者评论。原有功名案例边界问题仍在，本次没有修改数据库。

目前 case_search_view 只提取案例开头问事句，案例向量不包含完整盘面结构；加入“官鬼酉化申、世爻月破”不会自动实现案例盘面匹配。关键词/向量的 best-rank 合并也不是适用性精排，模型改写不能独立解决这一点。

最终解释 JSON 与引用通过，但语义仍不合格：无依据映射“准备不足、信心动摇”，混入内部校正文字，案例比较过于概括。检索节点接通不代表解卦输出质量通过。
