# 案例通道接入 v2

2026-10-11

## 当前链路

`/liuyao/hybrid/evidence` 读取服务端冻结盘，在 `stage9-text-reasoning-v2` 上执行规则和案例混合检索。最多返回 8 条规则、4 条案例；按问句检索视图召回后，沿来源定位回读完整案例原文。模型调用收到同一个 `reasoning_evidence`，其中 `kind` 区分规则和案例。

新快照复用 stage7 向量，包含 36 条文字规则和 207 条具有 `verbatim_extraction_validated` 问句检索视图、`reviewed_manual_boundary` 边界审核记录的案例。不是把全部 216 条案例或早期 253 条候选无差别发布，也没有新增教学测评材料。

发布清单增加独立 `case_allowlist`，绑定实体、视图、审核状态和元数据哈希。案例只获准 `analogy_only` 用途，旧 production_eligible 标志不修改，旧执行规则模式不放宽。撤销、排除、原文哈希及已知方法冲突检查继续生效。古例未标注 method_profile_id 时允许作为文字参考，但不声称与当前排盘算法一致，不参与程序取用证明。

## 检索和解释

- 规则与案例分别进行 BM25、向量召回和排名融合。案例查询包含对象、专题、目标、原问题和古文别名，例如考试对应“功名、科举、科舉、鄉試”。别名仅用于检索，不写入用户事实。
- provider 校验失败时继续 BM25，并保留降级记录。代码支持向量路径不代表每次运行都成功调用远程服务。
- 案例附带 `case_context`：案例与组 ID、问句/盘面/断语/结果的完整性状态、遗留问题和方法信息。缺项不补造。
- 可比性未知的案例可以展示，但不能宣称已经适用于用户；明确判定不可比的案例不送入模型文字分析。
- 候选、条件、最终选用的 evidence_ids 只接受规则 ID。案例 ID 只允许用于 readings 解释段。即使案例存在，无规则时也不生成候选用神判断。
- Prompt 要求比较相似点、差异和限制；不复制古例爻位到用户 core，不用古例填补用户缺失条件，不复制结果或应期。同组占问不能当成独立验证。
- 页面按规则/案例分别计数，展示古例原文、来源与资料限制。

程序验证引用和结构化事实，不能保证自由文本的语义推理全部正确；真实模型效果需继续测评。

## 构建和启动

```bash
PYTHONPATH=fortune_module4 fortune_module4/.venv/bin/python fortune_module4/scripts/prepare_liuyao_text_reasoning.py --include-cases
```

构建已完成。脚本对已存在快照拒绝覆盖；旧 v1 快照仍可用于回退。后端默认路径已改为 v2，运行中的服务需重新加载新代码；前端开发服务热更新，生产部署需重新构建。

## 验证覆盖

后端测试覆盖真实库案例返回、来源与缺项传递、撤销与排除、许可及原文篡改、旧 v1 隔离、无 provider 的 BM25 降级以及测试 provider 下的案例向量排名。前端测试覆盖案例传入实际 LLM 请求构造、案例解释引用，以及禁止案例替代候选/条件/选用规则。

模型请求测试和向量通道测试使用替身，不代表真实远程服务可用性或模型解读准确率。
