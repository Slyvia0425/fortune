# DDL 前卦面分析收敛实施方案

日期：2026-10-16。交接对象：聊天「审阅流程实施方案」。本文件是待实施方案，不代表代码已修改或测试通过。

## 1. 决策与范围

将默认 P1 从 LLM 自由生成分析任务，改成基于冻结卦盘、已确认问事和已验证取用的确定性任务生成。复用现有 PR4 查询编译、PR5 有界检索、PR6 结构化推理与展示，先解决规划不稳定、修复开销和覆盖漂移。

目标流程：确认问事 → 既有三数字起卦并冻结 → 既有固定取用 → 程序提取事实与关系 → 固定分析清单 → 查询编译与有界检索 → 结构化解释 → 校验与展示。

参考 liuyao-engine 的职责划分和结构化卦盘，不整体替换引擎，不引入运行时 Python 包依赖，不将三数字起卦改成铜钱起卦，不修改现有历法口径、不重新起已有卦、不重建知识库。

## 2. 当前实现与实际瓶颈

- `lib/server/analysis-planner.ts` 已编排问事 Q1、取用 R1、事实 F1、规划 P1，并复验冻结快照。
- `lib/divination/analysis-facts.ts` 已产出角色绑定、动爻、动变、空破冲、月令标签、伏藏及部分关系，事实具有稳定 ID。
- `lib/divination/fact-relations.ts` 已程序计算有方向的生克、同支、冲、合，且变卦六亲明确以本卦宫五行为基准。
- `lib/divination/analysis-plan.ts` 已有 `minimumAnalysisPlan()`；当前它是恢复路径，应先审计并提炼成正常的确定性生成器，不能简单把 fallback 改名后宣告质量改善。
- P1 当前仍依赖模型生成任务及定向修复；契约、自然语言事实校验、主题和覆盖约束增加了失败面。此处是架构上的可简化项，尚不能据此认定全部解读问题都来自 P1。
- 「审阅流程实施方案」最近一次已完成样例：本人三个月内找工作，数字 2/4/5，泽雷随五爻动变震为雷；流程约 102 秒且返回 complete，但实质结论未定。应复用已冻结记录回放，分别定位计划、检索和解释缺口，不能用 complete 代替有效分析验收。

## 3. DDL 必做：确定性 P1

新增 `lib/divination/deterministic-analysis-plan.ts`，输入沿用已验证的 question/use_roles/fact_catalog/core，输出兼容现有 InitialAnalysisPlan。生成函数为纯函数，不访问模型、网络、时钟，不改变原始事实。

任务按类别合并，保持现有七任务上限，使用现有 kind/topic 白名单，不为每个事实单独建任务：

| 分析块 | 触发条件 | 内容 |
| --- | --- | --- |
| 用神与世应 | 必需 | 使用既有角色绑定及候选，检索对应问事的判断条件，不重新取用 |
| 月日状态 | 关键角色有空破冲或月令标签 | 合并覆盖现有局部状态，明确局部标签不能直接作为综合旺衰 |
| 动变 | 关键角色存在动变事实 | 描述本支、变支、五行及已有方向关系；未核定的进退神仅作为待查条件 |
| 爻间关系 | 存在关键关系 | 覆盖世与用神、作用于关键角色的动爻关系，保持方向，不把结构生克当实际作用已成立 |
| 飞伏 | 相关角色伏藏 | 飞神位置、伏神状态、已有飞伏关系；不自动断可用或出伏 |
| 期限与应期 | 已确认问事含期限或问时 | 使用原期限和历法上下文；资料不足时保留缺口，不补造具体日期 |

任务模板须中性且有问题形式，fact_refs 只能来自本次目录，depends_on 使用确有必要的依赖。所有输出通过既有 validateAnalysisPlan；程序生成同样必须过引用、覆盖、重复、方向与主题校验。检查既有 coverageContract 是否漏掉需要的月令标签及期限覆盖，使用共享规则统一生成器和校验器。

P1 正常来源建议新增独立 `generation_mode: deterministic | llm` 与 `generator_version`；保持既有 status 的业务含义，规则正常生成可为 generated，不伪报 fallback。若为最小改动选择版本字段记录来源，也必须能从 trace 和 API 区分来源。检查 TS 契约、快照复验、Python runtime 中对 pipeline_version 的硬编码、UI 和测试，不只修改一个调用点。

接入 `buildInitialAnalysisPlan()`；默认 deterministic，保留明确的配置开关 `LIUYAO_PLANNER_MODE=deterministic|llm` 以便回退。LLM 路径保留但默认不执行；不能先调用模型再兜底确定性计划，否则不能减少失败面和延迟。Q1 与 R1 不在本轮重写范围。

## 4. DDL 必做：卦面事实包收敛

优先使用已有 FactCatalog 和 deriveCoreRelations，避免再造第二套完整排盘 JSON。必要时增加一个只读派生分析视图，统一向 P1、PR6、trace 提供：角色及候选、相关爻状态、动变对、世用关系、飞伏关系、缺失项和版本来源。

审计 `selectCoreRelations()`：当前主爻间主要保留角色对角色关系，可能漏掉非角色动爻对关键角色的生克。若补齐，限定为动爻↔关键角色，保持稳定排序与去重，更新相关覆盖和测试，避免把全部两两关系送入模型。

第一阶段仅采用已存在且已校验的五行/地支结构关系。新增回头生克标签时，按“变爻 → 本爻”方向从已验证关系映射，不另算一套。未有审定规则的化进退、暗动、入墓、三合成局等不设为完成 DDL 的前置条件。

## 5. 参考项目的借鉴边界

参考版本：`yaomancy/liuyao-engine@53291663a4c733c4cbdfa174a8d3075475c07fd3`。

- 借鉴 `reading.py`：程序组装本变卦、取用及关系事实，解释层消费结构化数据。
- 借鉴 `analysis.py`：局部状态与最终判断分开；不照搬其类别取用映射和两现排序。
- 借鉴 `relations.py`：确定关系通过表和纯函数产生；不直接照搬“静爻日冲即暗动”、同五行差值即进退、三支出现即标成局等简化判断。
- 参考项目的变卦独立调用 cast_chart；本项目已明确 kin_basis=primary_palace，应保持现有口径，不能照抄导致变卦六亲变化。
- `guaxiang.py` 是固定象意文案，可后置增加静态说明，不能作为针对问事的断卦证据。DDL 阶段无需加入。
- 对照两个引擎的同一输入规则输出可以检查实现一致性，不能证明预测有效。若复制实质代码或表，应保留 Apache-2.0 及相关第三方署名；优先独立实现分层思路。

源码链接：https://github.com/yaomancy/liuyao-engine/tree/53291663a4c733c4cbdfa174a8d3075475c07fd3/liuyao

## 6. 检索和解释的最小调整

复用现有 query-compiler 和知识索引，优先固定模板产出覆盖定义、成立条件、例外的查询，避免把所有结构标签都变成必须检索的项目。保留现有预算和 PR5 检索上限；本轮不同时更换检索器、embedding 或重构 PR6。

PR6 输入明确区分：程序已核定的结构事实、需证据支持的规则适用条件、尚未解决的判断。结构事实不要求模型再用古籍证明“本爻是什么”，但将结构推广为暗动/有效生克/吉凶/应期时仍需适用依据。不能为了提高输出率放松事实引用校验。

面向用户的结果应能说明：关键卦面是什么、如何关联问事、支持与制约因素、当前可达到的判断、具体未决项。证据不足时可以只对有依据部分形成有限结论，不强行给 yes/no；同时不能仅罗列“资料不足”而遗漏已经确定的卦面信息。保留 partial/failed 与 complete 的现有技术语义，另外展示实质结论是否确定，勿把二者混为一谈。

## 7. 实施顺序与停损

1. 固化基线：复用当前 245 冻结记录及历史回放，记录 P1 模型调用次数、生成/修复耗时、任务覆盖、query 数、证据覆盖、整体耗时和结论未决项。不要重新起卦或覆盖历史 trace。
2. 提炼确定性生成器并接入配置开关，先不增加理论类型。更新版本、缓存键、检查点复验和跨语言契约。
3. 按样例实际缺口补必要的动爻→角色关系与共享覆盖；若无缺口，不扩大事实类型。
4. 小幅调整 PR6 输入和展示边界，复用原检索与推理链，完成回放和代表性回归。
5. 验收后默认启用 deterministic；保留旧模式开关与独立缓存，不删除旧链路、不做数据库破坏性迁移。

DDL 最小交付为步骤 1、2、4、5；步骤 3 只做被样例和测试证实必要的关系补齐。不得扩展为完整六爻专家系统，也不要继续把本轮变成 P1 Prompt 调优工程。

## 8. 验收标准

- 同一冻结输入与版本重复生成计划，序列化输出和 plan_hash 一致；默认 P1 模型调用为 0，取用与问事调用另计。
- 原问题、期限、chart_id/chart_hash、confirmation_id/question_hash 均不改变；两个模式之间缓存与检查点不串用，旧快照按版本重建而非伪装兼容。
- 有期限必有 timing 任务；关键角色空破冲及相关动变无遗漏；角色多现、伏藏、无动爻、多个动爻、资料未知均有明确行为，不自动挑定未经审定的候选。
- 245 样例必须说明世爻月破、官鬼/世爻关系和酉→申变化；进退与三个月应期如未核定应保留明确缺口。不得以改成肯定答案作为通过标准。
- 代表性固定样例覆盖本人求职、非本人/不支持问事、财运、伏神、多现、无动爻及有期限；不支持取用继续遵循已有边界，不为凑覆盖添加粗糙分类。
- 模型或检索异常仍保留原卦、可恢复状态及基础解释；结构事实可展示，不能生成无依据结果。
- 执行 typecheck、受影响 Vitest 与 Python 契约测试。至少回放 245 并与基线比较 P1 与总耗时、覆盖和缺口；不能预先承诺整体提速倍数或断卦准确率提升。
