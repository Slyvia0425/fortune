本阶段仅调整 PR-5，不修改冻结问题、起卦、P1 语义或 PR-6 超时策略，也不进入下一阶段。

## 新的模型契约

```json
{
  "decision": "retrieve_more",
  "proposals": [{
    "parent_task_id": "T03",
    "trigger_type": "task_gap",
    "topic_ids": ["month_break"],
    "knowledge_need": "查找月破的例外及成立条件"
  }]
}
```

模型不再填写 request_id、fact_refs、priority、target_type、keyword_terms。程序从可信任务和事实目录派生这些字段；knowledge_need 不参与拼接自由检索词。最多三个请求、最多一个 optional、最多两轮等控制不变。

直接 task_gap 只能检索父任务已有主题。source_gap / frozen_fact 另需 trigger_ref：程序在输入中提供、关联原始父任务和真实首轮原文片段或未列入任务的相关冻结事实的句柄。句柄允许主题也由程序计算。句柄不是自由填写的新证据，不允许跨父任务引用、递归扩展或自动继承任意主题。

原文出现伏神而当前冻结事实没有伏神，扩展只允许查定义，不宣称盘中存在伏神。文本主题匹配仅是可追溯扩展的必要门槛，不代表已经完成专家适用性核对。

生成的正式请求仍经过原有 validateGapAnalysis / QueryCompiler 校验；初始计划保持不变。旧正式请求校验器保留作内部防线，不再作为模型输出契约。

## 错误与受控诊断

ValidationIssue 包含 code、path、received、可选 expected；区分未知任务、未知主题、越界主题、缺少触发依据、模型误填事实/优先级、JSON/契约错误、重复查询、预算延期等。

第二次调用包含第一次原始输出和字段级错误，不再只给笼统错误码。重复查询过滤与 optional 预算延期有不同原因，不要求模型反复修复已知重复。

每次调用的初始/修复原文、校验结果、耗时和错误写入 `.runtime/gap-diagnostics/`，以 diagnostic_run_id 定位。目录 0700、文件 0600、文件独占创建；路径已被 Git 忽略，不写入公开知识库或公开响应。不额外保存完整提示词、用户问题、cookie 或密钥；但模型原文仍可能包含用户隐私，因此日志必须仅限开发运维访问，不能上传公共日志平台。当前不自动删除取证文件，上线时需按部署隐私政策设置保留与清理期限。

诊断写入失败会停止补检并保留首轮结果，不会静默执行无审计的第二轮。对外只给诊断编号和安全的停止码，不返回原文及携带原文值的字段级错误。

G1 提示版本升至 g1-intent-compiler-v2，现有缓存身份已包含该版本，避免误复用旧 G1 结果。
